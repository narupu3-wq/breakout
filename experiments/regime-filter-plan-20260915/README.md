# 方向フィルター比較の事前計画

2026-09-15 13時レビューで登録。まだ実装・成績評価・常駐開始はしていない。

仮説は1件のみ：BTC平均回帰でsignal.sideと過去8時間騰落が逆符号なら新規entryを見送る。具体式はsignal.side*(current.close/history[-33].close-1)<0。ゼロは見送らない。ETH、トレンド、費用、数量、損切り、時間退出、日次/全体リスク、ゲートを変更しない。過剰なシグナル削減の可能性も反証対象。

探索対象は現行DBに保存済みのBTC/ETH15分足、1788732000以上1789380000未満。BTC720足確認。分析時に読み取りトランザクションからJSONへ書き出しSHA256と銘柄別範囲/欠損を固定する。連続性・銘柄時刻が合わなければ比較を停止して報告し、補間しない。先頭33足はwarmup、終了時の保有は同一の強制終了規約を使う。

固定engine/history_runの処理を使い、同一足でフィルター有無を全8候補・通常/倍費用で比較。別の一時DBのみ。主評価は純損益・最大DD・取引数・損失停止・費用倍の変化。取引0や少数だけの改善を採用根拠にしない。全候補の失敗も保存。既知の期間なので探索と明示する。

履歴結果後の閾値調整・候補追加なし。改善が見られても未使用データの評価計画を別途固定し、現在の常駐版と自動置換しない。稼働観測版は同時1版上限を維持。次の実装は既存パターンに沿う限定スクリプトとしてLuna maxの対象にできるが、この回は計画のみで委譲なし・使用量測定なし。
